# OmniConvert 产品与系统设计规格

日期：2026-10-19  
状态：已由用户确认  
目标官网：<https://www.sinxysai.site/>

## 1. 目标与原则

OmniConvert 是面向学生和研究者的跨平台文件与公式工具。用户能在一个应用中继续最近任务、转换常见文件、压缩图片，并将手写数学公式识别为可编辑的 LaTeX。

项目追求生产级工程质量和低运营成本，不以盈利为目标。第一版不接支付。官方公式识别使用免费额度和限流控制现有腾讯云服务器的负载。用户也可以配置自建识别服务。客户端、本地处理核心和自建接口采用 Apache-2.0 开源；官方识别服务、账号服务及运营配置保留在私有仓库。

设计原则：

1. **本地优先**：能够在设备上完成的处理默认不上传文件。
2. **访客优先**：本地工具无需账号；官方云端识别要求登录。
3. **明确告知执行位置**：每次云端处理前展示上传目标、文件类型和清理规则。
4. **低成本起步**：复用现有服务器，避免初期引入 GPU、付费 CDN、对象存储、短信和支付系统。
5. **可替换接口**：识别服务通过公开协议接入，客户端不依赖官方后端才能运行。
6. **质量可验证**：每项功能有明确的平台支持矩阵、错误状态和验收标准。

## 2. 用户与典型任务

首批用户是学生和研究者。常见任务包括：

- 拍摄或导入手写公式，取得 LaTeX 和渲染预览，复制到论文或笔记。
- 将 DOCX、MOBI、图片转换为 PDF，或将 PNG 转为 JPEG。
- 压缩论文插图、课件图片，并控制输出质量与尺寸。
- 在首页找到最近文件与任务，重新下载结果或重试失败任务。

首页以“最近文件与任务”为主要入口，提供“公式识别、文件转换、图片压缩”三个快速操作。工具列表按“公式、文档、图片”分组。设置包含账号、识别服务、默认输出位置、隐私、更新及关于。

## 3. 范围与阶段

### 3.1 第一阶段：可公开试用的基础版

- 官网首页、下载页、版本说明、文档入口及 Web 轻客户端入口。
- Flutter 客户端在 Windows、Linux、Android、Web 上可构建和使用；macOS 与 iOS 在 macOS CI 上完成编译验证。
- 桌面端本地执行 PNG→JPEG、PNG/JPEG→PDF、图片压缩。
- Android 端本地执行图片类功能。
- Web 轻客户端在浏览器中执行图片类功能；不承诺大型文件的浏览器内处理。
- 桌面端提供可选的 DOCX→PDF、MOBI→PDF 外部转换器适配器；未检测到依赖时明确提示安装方式。
- 统一任务列表、进度、取消、失败提示、重试和最近文件记录。
- 公开识别 Provider 协议、自建 Provider 配置及契约测试。
- 官方 CPU 小模型识别服务的基础链路、账号及免费额度。若模型质量未通过验收，公开试用范围先限于自建 Provider，官方服务不标记为可用。
- 官网 APK 下载与 Android 应用内版本检查、下载和系统安装器更新流程。

### 3.2 后续阶段

- iOS 原生 App 正式分发、macOS 签名及公证。
- 移动端和 Web 的 DOCX/MOBI 云端转换。
- 跨设备任务同步、批量公式识别、批量文件转换。
- 需求和服务负载明确后，才评估付费订阅、GPU、对象存储与 CDN。

第一阶段不包含支付、协作编辑、云盘、复杂 PDF 编辑、无限期文件托管或各平台完全一致的格式转换能力。

## 4. 平台能力与分发

| 平台 | 第一阶段处理能力 | 构建环境 | 分发与更新 |
| --- | --- | --- | --- |
| Windows | 图片本地处理；DOCX/MOBI 可选外部适配器 | Windows | 官网安装包；应用内检查、下载并引导安装 |
| Linux | 图片本地处理；DOCX/MOBI 可选外部适配器 | Linux | 官网安装包；应用内检查、下载并引导安装 |
| macOS | 与桌面端同一设计，CI 编译验证；实际转换依赖 macOS 验证 | macOS + Xcode | 官网构建包可供测试；未签名包有系统安全提示 |
| Android | 图片本地处理、官方或自建公式识别 | Windows/Linux | 官网 APK；应用内下载更新并调用系统安装器，需用户确认 |
| iOS | Flutter iOS 工程和 CI 无签名编译验证；开发者可自行签名安装 | macOS + Xcode | 第一阶段公众使用 PWA；原生公开分发后置 |
| Web | 图片类轻量处理、官方或自建公式识别 | Windows/Linux | 官网 `/app/`，部署后更新 |

开源仓库允许开发者在满足平台 SDK、签名和系统要求的条件下自行构建全部六端。iOS 真机安装须由开发者使用自己的签名配置；公开原生 iOS 分发不属于第一阶段。macOS 和 iOS 的 Apple 平台构建只在 macOS Runner 运行，Windows/Linux 开发环境无需伪装成 Apple 构建环境。

Android 官网 APK 采用稳定应用 ID 和同一签名密钥。更新包应验证签名、版本号与 SHA-256；安装由 Android 系统安装器和用户确认完成。不能承诺静默安装。应用商店版如果日后发布，按对应商店政策单独处理。

## 5. 系统结构与仓库边界

```text
公开仓库 omniconvert-client
  Flutter UI（桌面、移动端、Web）
  Rust 本地处理核心（Windows、Linux、macOS、Android、iOS）
  Web 图片处理实现（浏览器能力；不直接使用原生 Rust FFI）
  统一任务模型与本地持久化
  OCR Provider 协议、官方服务客户端、自建服务适配器
  多平台构建脚本、测试与文档

公开仓库 omniconvert-site
  静态官网、下载页、版本说明、使用和自部署文档

私有仓库 omniconvert-backend
  账号与会话、额度、官方 OCR 推理、任务与发布元数据
  运维配置、密钥和管理工具
```

公开仓库边界是接口，不共享私有业务实现。官网和 Web 轻客户端可从两个仓库单独构建，部署到同一个域名。公开仓库使用 Apache-2.0；外部二进制和模型的许可证单独审查，不因仓库许可证而自动获得再分发权。

目标路由：

| 路径 | 用途 |
| --- | --- |
| `/` | 官网首页 |
| `/download/` | 平台安装包、校验值、安装说明 |
| `/releases/` | 版本说明 |
| `/docs/` | 使用、开发与自建 Provider 文档 |
| `/app/` | Flutter Web 轻客户端 |
| `/api/v1/` | 官方 API |

这些路径是规划中的部署目标。现有域名内容、DNS、反向代理和证书覆盖范围在部署前检查，设计阶段不修改线上站点。

## 6. 核心模块与接口

### 6.1 工具目录

每个工具声明 `toolId`、输入格式、输出格式、支持平台、执行位置和配置字段。UI 依据能力矩阵显示可用、需安装依赖或不可用状态。后端增加新工具不能自动使所有客户端平台显示为可用。

### 6.2 任务引擎

通用任务数据包含：`taskId`、`toolId`、`source`、`target`、`executionMode`、`status`、`progress`、`createdAt`、`updatedAt`、`result` 和结构化 `error`。`executionMode` 取 `local`、`self_hosted`、`official_cloud`。

状态流：

```text
queued → running → succeeded
                 ↘ failed → queued（显式重试）
                 ↘ cancelled
```

本地任务只在设备保存本地路径、任务参数和结果元数据。云端任务只在服务端保留完成处理所需的最小元数据。客户端重启后可恢复任务列表；未完成的本地任务标记为“已中断”，由用户重试，不假装后台处理仍在进行。取消操作应终止可控的子进程并清理临时文件。输出先写临时文件，成功后原子移动到目标位置，避免生成看似完整的损坏文件。

### 6.3 本地转换适配器

- 图片转换和压缩由 Rust 核心或平台可用的本地实现完成；控制图片尺寸、质量、透明背景处理、色彩空间和 EXIF 保留策略。
- PNG/JPEG→PDF 保留可选择的页面尺寸、方向、边距与图片缩放策略；多图合并作为后续功能。
- DOCX→PDF 调用用户安装的 LibreOffice 等外部程序；记录实际转换器版本和退出码。
- MOBI→PDF 调用经验证的外部转换程序；先做样本质量与许可证评估，不把示例中的图像型 MOBI 处理结果当成所有 MOBI 的保证。
- 外部转换器未安装、格式受 DRM 保护、密码受保护、文件损坏或字体缺失时，分别给出可理解的错误。

外部程序默认不随 Apache-2.0 客户端捆绑。若以后捆绑，先完成各工具许可证和再分发义务审查。移动端不依赖桌面外部程序。

### 6.4 公式识别 Provider

公开协议至少包含：能力查询、单张图片识别、取消或超时、结构化错误。识别请求包含图片、语言/数学模式、客户端生成的幂等键和最大等待时间。响应包含 LaTeX、可选置信信息、模型/服务版本和警告。客户端本地渲染 LaTeX 预览，用户可编辑、复制和导出。

Provider 分为官方云端与用户配置的自建服务。自建服务地址由用户设置，客户端显示目标域名并通过 HTTPS 发送；本地开发可显式允许 HTTP。自建 Provider 是否要求认证由该服务配置决定。官方 Provider 使用登录会话和免费额度，不接支付。

官方服务应在正式开放前建立覆盖常见手写、分式、上下标、矩阵、多行公式和低质量照片的评估集。先设定样本集和人工评审规则，再确定可接受质量阈值；未达到阈值时不宣传“准确识别”。模型许可证、权重来源和 CPU 延迟均需记录。

### 6.5 账号与免费额度

本地工具无需登录。官方 OCR 要求登录，以便可靠地限制额度。第一版账号使用邮箱与密码，密码以 Argon2id 哈希保存；注册验证、找回密码通过配置的 SMTP 邮件通道发送短期有效链接。若部署时没有可用的邮件通道，官方 OCR 不能向公众开放注册，自建 Provider 和本地工具仍可用。不能以设备 ID 单独作为可靠身份。

额度在服务端以事务方式扣减；同一幂等键的重试不重复计数。仅成功完成并返回有效结果的任务计入额度；服务器错误和超时不扣减。额度周期、每次消耗和并发上限属于可配置运营参数，默认值需依据 CPU 压测结果确定并在产品界面公示。超额时显示重置时间或自建 Provider 选项，不展示付费入口。

### 6.6 更新与发布

发布清单包含平台、架构、版本、最低兼容版本、下载地址、文件大小、SHA-256、签名标识和更新说明。客户端只接受 HTTPS 传输并校验安装包。更新检查失败不影响本地工具使用。

桌面端按各平台实际安装包类型下载并引导安装，不能把“检查到新版本”等同于“无提示自动替换运行中的程序”。Android 官网 APK 按上述系统安装器流程更新。iOS PWA 随部署更新；未来原生 iOS 的更新遵循实际分发渠道规则。

## 7. 数据与安全

本地任务默认不上传；上传到官方或自建 Provider 前必须展示处理位置。官方 OCR 原图在任务结束后 1 小时内清理，未结束的任务最迟在创建后 24 小时清理；结果历史默认仅保存 LaTeX 和必要元数据，用户可删除。上传和处理目录使用随机任务 ID、隔离权限、文件大小限制、文件类型校验和自动过期清理。服务日志不得记录图片内容、文件正文、访问令牌或完整本地路径。

API 使用 HTTPS、认证、请求大小限制、速率限制、任务超时和幂等键。外部转换程序以受限用户或容器执行，并限制 CPU、内存、磁盘和运行时间。服务器设置备份与恢复演练；备份只包含必要数据库数据，不默认备份上传原文件。

更新包签名密钥、服务令牌和模型访问密钥不进入公开仓库或 CI 日志。GitHub CI 使用最小权限，发布密钥只在受保护的发布作业中使用。隐私政策明确本地处理、官方上传、自建服务与数据删除规则。

## 8. 部署与成本约束

第一版复用现有腾讯云 Linux 服务器：反向代理、静态官网、API、数据库和 CPU OCR Worker 可先共机部署。使用容器和资源配额隔离 OCR 推理与 Web/API，避免推理占满机器。临时文件先使用受限服务器磁盘并设容量上限、定期清理和磁盘告警。Redis、COS、CDN、GPU、短信和支付均不是第一版依赖。官方账号注册和找回密码需要可用 SMTP；该通道是否有额外费用取决于部署环境与邮件提供方。

数据库先使用 PostgreSQL；任务队列初期使用数据库领取与租约机制，不依赖 Redis。监控从健康检查、结构化日志、基础指标、磁盘/CPU 告警和定期备份开始。现有服务器的 CPU、内存、磁盘和带宽容量需压测后才能确定官方 OCR 免费额度；设计不保证零增量成本或无限并发。

官网使用静态站点生成器，Web 轻客户端单独构建部署到 `/app/`。安装包可通过官网文件目录或 GitHub Releases 提供；下载页面始终提供校验值。若访问量升高再评估对象存储或 CDN。

## 9. 构建、测试与验收

CI 矩阵：Windows Runner 构建 Windows；Linux Runner 构建 Linux、Android 和 Web；macOS Runner 构建 macOS 并执行 iOS 无签名编译检查。Apple 平台发布签名不作为开源 CI 的默认要求。公开仓库必须提供本地开发说明、系统依赖、构建命令、失败排查和兼容平台版本。

验收条件：

1. 访客离线完成 PNG→JPEG、图片压缩和图片→PDF；任务结果可重新打开，失败可重试。
2. DOCX/MOBI 外部适配器在支持的平台上能检测依赖，并用代表性样本验证可用范围；不支持的输入给出具体错误。
3. 官方云端识别前明确提示上传，成功返回可编辑 LaTeX 和预览；服务不可用时本地工具仍可运行。
4. 免费额度在并发和重试下不重复扣减，超额时返回可解释的状态。
5. 自建 Provider 可根据公开协议实现，并通过契约测试连接客户端。
6. Android 官网 APK 能以同一签名密钥安装升级；更新包校验失败时不会启动安装。
7. 六平台构建矩阵运行；iOS 的验收是无签名编译与开发者自签文档，不等同于公众直接安装。
8. 官网下载页对应最新版本清单，链接、哈希和更新说明一致。
9. 服务器在文件大小、任务并发、处理超时和磁盘配额限制下保持可用，并有可执行的备份恢复步骤。

## 10. 实施拆分

本规格是总体架构，后续按独立计划实施：

1. 公开客户端骨架与跨平台 CI。
2. Rust 图片处理、任务引擎及本地历史。
3. 桌面文档转换适配器与格式质量验证。
4. 官网、文档、下载页与更新清单。
5. OCR Provider 协议、自建适配器和官方 CPU 小模型服务。
6. 账号、免费额度与服务端安全运维。

每一项进入开发前再写具体实施计划和验收样本。平台签名、域名部署、实际模型和转换器选型以当时的可用性及许可证审查为准；这些选择不改变本文确定的接口和产品边界。
